# Размещение MoneyGraph

## Что хранится

Для одного экземпляра приложения достаточно существующей SQLite. Аккаунты должны храниться на постоянном диске: в контейнере это `/state/users.sqlite3`. Результаты расчёта находятся в `/state/output`. Исходные `nodes.parquet`, `edges.parquet`, `transactions.parquet` подключаются отдельно в `/data`, только для чтения. Эти данные, локальные аккаунты и OAuth-секреты не включены в образ.

Для облачного размещения владелец выбрал Supabase. Приложение поддерживает Supabase Auth для аккаунтов и SQLite для автономного режима; режим задаётся через MONEY_GRAPH_AUTH. Сам граф продолжает рассчитываться из Parquet; переносить его в SQL ради демонстрации не требуется.

## Подключение Supabase

Для аккаунтов подключён Supabase Auth: регистрация, подтверждение email, вход по паролю и восстановление через почту. Google через Supabase требует отдельной интеграции OAuth callback; текущая облачная версия использует email. Пароли в собственную таблицу PostgreSQL не переносим. Локальные аккаунты SQLite автоматически аккаунтами Supabase не становятся.

Для интеграции нужны URL проекта и publishable key (или legacy anon key). Значения следует задать в секретах хостинга; service_role, secret key и пароль PostgreSQL для обычного входа пользователей не требуются. Настройки задаются в разделе [supabase] локального secrets.toml либо переменными окружения. Полный список и проверка входа: [AUTH.md](AUTH.md). В Compose передайте MONEY_GRAPH_AUTH=supabase, SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY и MONEY_GRAPH_ALLOWED_EMAILS через окружение или локальный .env, исключённый из Git.

После выбора адреса приложения нужно настроить Site URL и разрешённые redirect URL в Supabase Auth, провайдера Google и доставку писем. Доступ к аналитическим данным должен предоставляться только согласованной аудитории, независимо от возможности создать аккаунт.

Исходные Parquet можно оставить на сервере или разместить в приватном Supabase Storage. Во втором случае потребуется отдельная загрузка файлов на сервер перед расчётом. Подключение Supabase Auth само по себе не переносит файлы и не публикует Streamlit-приложение: хостинг Python-приложения выбирается отдельно.

Документация: [Supabase Auth](https://supabase.com/docs/guides/auth), [Google](https://supabase.com/docs/guides/auth/social-login/auth-google).

## Docker на компьютере или сервере

Нужны Docker Engine с Compose и три исходных файла в папке `data`. Из корня проекта:

```bash
docker compose up --build -d
docker compose logs -f moneygraph
```

После расчёта откройте `http://127.0.0.1:8504`. При каждом запуске контейнера выполняется исходный pipeline. При ошибке входных данных сервер не запускается. Первый запуск создаёт отдельное хранилище аккаунтов; аккаунты локальной версии автоматически не переносятся.

```bash
docker compose ps
docker compose restart moneygraph
docker compose down
```

Обычный `down` сохраняет именованный volume. `down --volumes` удаляет аккаунты и результаты. Для резервного копирования остановите сервис и сохраните содержимое volume средствами хостинга; восстановление требует того же постоянного хранилища и доступа на запись для UID 10001. Исходные Parquet храните отдельно.

## Размещение в интернете

Используйте ветку `codex/ui-alisher`, Dockerfile в корне и один экземпляр сервиса. Постоянный диск подключается в `/state`, исходные файлы — в `/data`. Если хостинг требует свой порт, задайте `STREAMLIT_SERVER_PORT` этим числом. Health check: `/_stcore/health`; начальный расчёт может занять до пяти минут. HTTPS и WebSocket должны проксироваться к порту Streamlit.

Compose публикует порт только на loopback сервера. Для удалённого просмотра можно использовать SSH-туннель `ssh -L 8504:127.0.0.1:8504 user@server`. Для общей ссылки подключите HTTPS-прокси или управляемый хостинг.

В режиме Supabase сервер проверяет подтверждение email и список MONEY_GRAPH_ALLOWED_EMAILS. SQLite-режим предназначен для локального просмотра и не проверяет владение почтой: для удалённого автономного режима ограничьте доступ на стороне VPN/хостинга. Перед публикацией проверьте вход разрешённого пользователя и отказ постороннему.

Отдельный Google OIDC в локальном режиме настраивается по [AUTH.md](AUTH.md). Подключите секретный файл только для чтения в `/app/.streamlit/secrets.toml`, задайте redirect URI `https://ВАШ-ДОМЕН/oauth2callback` и тот же URI в Google Cloud. После настройки проверьте полный цикл входа и выхода. Секреты и базу аккаунтов не отправляйте в Git.

Размещение ещё требует выбранного хостинга, доступа к аккаунту владельца и переноса исходных данных. Подготовленные файлы не означают, что приложение уже опубликовано.

Документация: [Streamlit в Docker](https://docs.streamlit.io/deploy/tutorials/docker), [постоянные диски Render](https://render.com/docs/disks). У Render постоянный диск доступен для платного сервиса; бесплатный сервис не сохраняет локальные изменения между пересозданиями.
